# Evermoon

Flutter app to register yearly events on Vietnamese lunar dates (mainly death anniversaries, "giỗ") and remind the user about them. Registration and reminders are the core; the lunar calendar view is a supporting feature. Personal use first; shared family groups later. Project name: Evermoon. Dart package and folder name: `ever_moon`.

Full product context: `docs/PRODUCT_BRIEF.md`. Read it before designing features.

## Domain rules (decided, do not re-litigate without the user)

**Lunar date storage**
- A death anniversary stores `lunarDay` + `lunarMonth` (required) and `deathYear` (lunar year, optional). Never require or hard-validate the year; many families only remember day and month.
- `diedInLeapMonth` is only meaningful when `deathYear` is set and that year has a leap month with the same number as `lunarMonth`. The UI shows this toggle only in that case; otherwise it is ignored and stored as `false`.

**Which month is used in a given year Y**
- No `deathYear`, or not `diedInLeapMonth`: always the regular month.
- `diedInLeapMonth` is true: if year Y has a leap month with the same number, use that leap month; otherwise use the regular month. The anniversary therefore never disappears.
- A manual per-event override (`regular` / `leap` / `both`) is not in v1. Revisit only if the family asks for it.
- Day 30 in a 29-day month: fall back to day 29.
- Needs an engine query "does lunar year Y have a leap month, and which number?". The own package (see Lunar engine) must expose it.

**Reminders (v1)**
- Remind on the exact anniversary day only. No "tiên thường" (day-before) logic. Optional lead-days may be added later.

**System events** (no user creation, only toggle reminders): mùng 1, rằm, traditional Tết festivals.

**Lunar engine**
- Use the Vietnamese rules (time zone UTC+7), never a Chinese-calendar (UTC+8) library.
- We implement our own pure-Dart package `packages/lunar_calendar` (plan: `docs/plans/0001-lunar-package.md`), from the published rules and astronomical formulas, for lunar years 1800 to 2199. Do not copy or translate the original JavaScript of Hồ Ngọc Đức (licence unconfirmed). Use the same convention as his published tables (Meeus new moon, UTC+7). The app reaches it only through our own `LunarCalendarService` interface.
- Tests must compare against the independent oracle fixtures in `packages/lunar_calendar/test/fixtures/` (generated by `tools/lunar_oracle/`, see its README). Never hardcode expected solar dates from memory or from the model's own computation.
- The `n % 19` leap-year trick is only a mental shortcut. Do not use it in code.

**Groups (phase 2, do not build before 3–5 relatives use the personal version)**
- Roles: Owner / Editor / Viewer. Allow multiple owners.
- Owner can name a successor. If all owners are inactive for a long period, a member can request ownership, confirmed by another editor, with a waiting period.
- "Request edit" and "request ownership" are separate flows.
- Use neutral wording for inactive owners (the owner may have passed away).

**Architecture**
- Offline-first. Stable IDs on every entity so sync can be added later without a rewrite.

## Open questions (need family input, not blocking)
- Does anyone in the family actually have an anniversary in a leap month?
- Confirm custom for leap-month years with relatives. The decision so far is "regular month", which is a design default, not a verified tradition.

```bash

fvm flutter pub get

fvm flutter run --flavor dev -t lib/main_dev.dart
fvm flutter run --flavor prod -t lib/main_prod.dart

# Analyze
fvm flutter analyze

fvm flutter test

fvm flutter test test/widget_test.dart

fvm flutter pub run build_runner build --delete-conflicting-outputs

fvm flutter pub run build_runner watch --delete-conflicting-outputs

fvm dart pub global run flutterfire_cli:flutterfire configure \
  --project=<firebase-project-id> \
  --out=lib/firebase/<flavor>/firebase_options.dart \
  --platforms=android,ios
```

## Key conventions

**State management** — use Cubit (not full Bloc) for all state. Each page owns its own Cubit, instantiated inside `initState` and closed in `dispose`. The global `AppCubit` is provided at `AppPage` level via `MultiBlocProvider`.

**Navigation** — GoRouter with `StatefulShellRoute.indexedStack` (shell tabs: home, setting). Always navigate using `context.go(Routers.x.routerPath)` or `context.goNamed(Routers.x.routerName)`, or the helpers in `router_extension.dart`. Never use `Navigator.push` directly. Add new routes to the `Routers` enum first, then wire them in `router_config.dart` (order matters — GoRouter matches top-to-bottom).

**Flavors** — two flavors: `dev`, `prod`, each with its own entry file (`main_<flavor>.dart`) that delegates to `main.dart`. The active flavor is detected at runtime from the bundle-ID suffix (`PackageInfo.flavor`) and drives `AppEnv.load` and the native Firebase config. Always pass `--flavor <env> -t lib/main_<env>.dart` when running or building.

**Firebase init** — Firebase is auto-initialized by the native layer (Android `google-services.json` per flavor under `src/<flavor>/`; iOS `GoogleService-Info.plist`). Dart calls `Firebase.initializeApp()` with **no options** to attach to the already-running native instance. The background FCM handler is a top-level `@pragma('vm:entry-point')` function.

**Theming** — colors come from the palette in `common/app_colors.dart` / `app_themes.dart`. Never hardcode colors in widgets; reference `Theme.of(context).colorScheme` or the palette constants. Dimensions, text styles, shadows, gradients and animations also live in `common/`.

**Barrel exports** — each Dart module/package has exactly one barrel file `lib/<module>.dart` declaring `library <module>;` and exporting its public API (`base.dart`, `common.dart`, `pages.dart`, `routing.dart`, `utils.dart`, `extensions.dart`). Register with `include: [<pkg>]` in `dartdoc_options.yaml`.

**Code generation** — Retrofit API clients and JSON models require `build_runner`. Run it after any change to files annotated with `@RestApi` or `@JsonSerializable`.

**Localization** — ARB files live in `lib/l10n/` (`intl_en.arb` is the template, `intl_vi.arb` must have the same keys). Flutter `gen-l10n` (config `l10n.yaml`) regenerates `lib/generated/l10n*.dart` on `pub get` and `run`, or with `fvm flutter gen-l10n`. Use `S.of(context).keyName`; there is no `S.current`, so code without a `BuildContext` takes an `S` parameter (see `onValidate`).

**Logger** — use `simpleLog()` for quick debug prints, `info()` / `warn()` / `err()` for structured logs.

**Iterable wrappers** — when a class wraps a single primary `List<T>` (e.g. response wrappers, list-backed states), mix in `Iterable<T>` and override `iterator` so the object itself is iterable — no need to reach into the inner list. This exposes the full lazy `Iterable` API (`map`, `where`, `length`, `isEmpty`, `first`, spread `...`) directly on the object. `with Iterable<T>` needs no extra import and coexists with `Equatable` (which only overrides `==`/`hashCode`). Keep it null-safe with `data ?? const []`.

```dart
// Declaration — ArrayResponse<T> exposes its `data` list as an Iterable
class ArrayResponse<T> extends Equatable with Iterable<T> {
  final List<T>? data;
  // ...
  @override
  Iterator<T> get iterator => (data ?? const []).iterator;
}

// Usage — iterate / filter / map straight on the response, no null-checks
Future<void> loadUsers() async {
  final res = await repo.getUsers();          // ArrayResponse<User>
  final names = res.where((u) => u.isActive).map((u) => u.name).toList();
  final count = res.length;                   // instead of res.data?.length ?? 0
  final first = res.firstOrNull;
  final tiles = [for (final u in res) UserTile(u)];
}
```

Only apply this when there is exactly one unambiguous list to iterate. For a class holding several lists (e.g. `HomeSuccess` with both `data` and `archived`), the mixin iterates only `data` — keep the named fields for anything else so intent stays clear.

**Comments & style** — all code comments in **English**. Section headers use `// TITLE` only (no bordered `// ---` style). Don't force unrelated classes into a shared base just for consistency. Lint: `flutter_lints` with `prefer_const_constructors` enabled; `no_leading_underscores_for_local_identifiers` and `slash_for_doc_comments` disabled.

**Local packages** — new local packages go in `packages/` (this project's rule; the template used `pkgs/`); prefer pure Dart and strip unused plugin/native boilerplate and deps. When vendoring external code, remove owner info and keep the original license as `Copyright (c) <year> Fox`.

## Hard rules (inherited from the workspace conventions, Flame rules excluded)
- State: Cubit (flutter_bloc) only. One Cubit per page, created in `initState`, closed in `dispose`. Sealed, Equatable states, never one class with nullable fields. No `setState` for business logic.
- Navigation: GoRouter only. Add the route to the `Routers` enum first, then `router_config.dart`. Use `context.go()` / `context.goNamed()`.
- Comments: English only. Public API uses `///` DartDoc. Comment why, not what.
- Widgets: every distinct UI piece is its own widget class, no `_buildX()` helpers. `const` where possible. `ListView.builder` for dynamic lists.
- No hardcoded colors, paddings, dimensions or user-visible strings. Use theme/`AppColors`/`AppDimensions` and `S.of(context)` (ARB; Vietnamese is the primary locale).
- Async: `async`/`await` only, no `.then()`. Avoid `!`; if unavoidable, comment why it is non-null.
- Every `catch` logs or rethrows. No bare `print()`, use `AppLogger`.
- Max 20 lines per function. Run `fvm dart analyze` before every change, zero warnings.
- After editing `@JsonSerializable` files run build_runner; after ARB edits run `fvm flutter gen-l10n`. Never hand-edit generated files.
